================================================================================
          PROJECT NOVA - AI SYSTEM ARCHITECTURE & CODE EXPLANATION
================================================================================

1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Project NOVA is an intelligent, local-first hybrid AI assistant that dynamically
routes user questions to either:
  a) Internal Parametric Model Memory (for static math, algorithms, definitions)
  b) Live Grounded Web Retrieval (for dynamic news, sports, prices, fresh events)
  c) Internal Document Vector Store (for private PDFs / uploaded files)

NOVA is designed around Adaptive-RAG, Self-RAG, and Corrective-RAG (CRAG) principles
to eliminate LLM hallucinations by enforcing strict, claim-level bracketed citations
([1], [2]) pointing directly to verified web sources.


2. THE 4 CORE AI CODE MODULES
--------------------------------------------------------------------------------

MODULE 1: The Model Socket Interface (Abstract Base Class)
File: carrot.webtool/core/base_model.py
Class: BaseLLMAdapter
--------------------------------------------------------------------------------
This is the single most important architectural file for your future AI models.
It defines 4 strict contracts that any language model must implement:
  - generate(): Generates plain text responses.
  - generate_structured(): Forces the model to respond strictly according to a
    Pydantic JSON schema (used for classification and routing).
  - stream(): Streams output tokens chunk-by-chunk for live typing in the terminal.
  - get_embeddings(): Converts text into dense vector representations.

WHY THIS MATTERS:
When you train your own proprietary PyTorch or HuggingFace model in the future,
you do NOT touch the router, search engine, or citation code. You only create
`models/my_custom_model.py` inheriting from `BaseLLMAdapter`, and NOVA will run
on your own custom model immediately.


MODULE 2: The Ollama Local Model Driver
File: carrot.webtool/models/ollama_adapter.py
Class: OllamaAdapter (Inherits from BaseLLMAdapter)
--------------------------------------------------------------------------------
This file bridges Python with your local Ollama runtime over HTTP (port 11434).
Key features implemented in this file:
  1. Real-time Streaming: Implements Python generator (`yield content`) so tokens
     appear on screen in real-time as the GPU/CPU generates them.
  2. Strict JSON Extraction: Calls Ollama with `format="json"`. It includes an
     automatic regex stripper for markdown code blocks (```json ... ```) and an
     automatic self-repair retry loop if the model emits malformed JSON.
  3. Dense Embeddings: Calls Ollama's `/api/embeddings` endpoint using the
     `nomic-embed-text` model to produce 768-dimensional vector arrays.


MODULE 3: The 3-Tier Intelligent Query Router (HMSQR Engine)
Files:
  - carrot.webtool/intelligence/signals.py  (Tier 0: Deterministic Heuristics)
  - carrot.webtool/intelligence/schemas.py  (Pydantic Data Contracts)
  - carrot.webtool/intelligence/router.py   (Tier 1 & Tier 2 Cascading Engine)
Class: IntelligentQueryRouter
--------------------------------------------------------------------------------
Instead of blindly searching the internet for every question (which wastes
time and money), this AI engine categorizes the user's intent in 3 cascading tiers:

  TIER 0 (0ms Latency Heuristics - signals.py):
    Uses compiled regular expressions to identify obvious queries:
      - Conversational greetings: "hi", "hello", "who are you" -> INTERNAL_LLM
      - Pure Mathematics: "calculate", "derivative of", "solve" -> INTERNAL_LLM
      - Algorithms / Code: "palindrome", "invert binary tree", "quicksort" -> INTERNAL_LLM
      - Document queries: "my uploaded pdf", "summarize file" -> INTERNAL_RAG

  TIER 1 (Semantic SLM Classification - router.py):
    If Tier 0 is inconclusive, it calls a fast Small Language Model (Qwen 2.5 1.5B)
    with a structured prompt. The model evaluates:
      - Knowledge Volatility:
          * VERY_LOW: Math, Physics, Grammar
          * LOW: Established CS algorithms, historical concepts
          * MEDIUM: Company leadership, product features
          * HIGH: Software releases, government policies, breaking news
          * EXTREME: Crypto/Stock prices, live sports, weather
      - Search Query Generator: If web search is needed, the model converts the
        conversational question into 1 to 3 crisp search keywords (e.g.,
        "who is new mentor of csk" -> ["Chennai Super Kings new mentor 2027"]).

  TIER 2 (Hard Policy Gatekeeper - router.py):
    Enforces safety rules:
      - If the query mentions post-cutoff dates (2025-2029) or keywords like
        "latest", "today", "current price", Tier 2 OVERRIDES the decision and
        mandates WEB_SEARCH to prevent outdated hallucinations.

  AUTONOMOUS DATASET LOGGING:
    Every routing decision (query, volatility, reasoning, search keywords) is
    appended to `data/routing_dataset.jsonl` to automatically build a curated
    fine-tuning dataset for your future custom model.


MODULE 4: The Grounded Answer Synthesizer & Citation Engine
File: carrot.webtool/main.py
Class: NovaOrchestrator
--------------------------------------------------------------------------------
This is the master coordinator. It handles the end-to-end conversation turn:
  1. Receives raw user prompt.
  2. Asks IntelligentQueryRouter to determine the knowledge path.
  3. If INTERNAL_LLM:
       Streams the response directly using pretrained parametric memory.
  4. If WEB_SEARCH:
       - Runs live DuckDuckGo dual-channel search (News + Web).
       - Runs parallel multi-threaded extraction using Trafilatura to clean HTML.
       - Formats evidence blocks with source indices:
           --- SOURCE [1]: Title ---
           URL: https://...
           CONTENT: Clean article body...
       - Constructs the Grounded System Prompt:
           "You MUST answer based strictly on the provided Web Evidence.
            Every factual statement MUST cite its source with [1], [2].
            If evidence lacks information, honestly state what is unverified."
       - Streams the grounded answer in real-time.
       - Prints the verified clickable source links beneath the answer.


3. STEP-BY-STEP TRACE: HOW A QUERY MOVES THROUGH THE AI CODE
--------------------------------------------------------------------------------

EXAMPLE QUERY: "Who is the new mentor of Chennai Super Kings?"

Step 1: Ingestion
  - User enters text in `main.py:NovaOrchestrator.process_query()`.

Step 2: Tier 0 Signal Analysis
  - `signals.py:analyze_signals()` checks regex patterns.
  - Detects temporal keywords ("new mentor"). Sets `has_temporal_trigger = True`.

Step 3: Tier 1 SLM Classification
  - `router.py` invokes `llm.generate_structured()` using `Qwen 2.5 1.5B`.
  - Model outputs JSON:
      {
        "primary_route": "WEB_SEARCH",
        "volatility": "MEDIUM",
        "is_time_sensitive": true,
        "search_queries": ["Chennai Super Kings new mentor", "CSK team mentor announcement"]
      }

Step 4: Tier 2 Gatekeeper Verification
  - `router.py:_apply_policy_overrides()` verifies that time-sensitive facts are
    locked to WEB_SEARCH.
  - Appends the trace to `data/routing_dataset.jsonl`.

Step 5: Live Retrieval & Extraction
  - `retriever/web_search.py` queries DuckDuckGo for keywords.
  - Returns 3 candidate URLs.
  - `retriever/extractor.py` launches a ThreadPoolExecutor to fetch all 3 URLs
    concurrently in under 1.5 seconds.
  - Strips all ads, banners, footers, leaving only high-density clean text.

Step 6: Grounded Synthesis
  - `main.py:_format_evidence_context()` labels each document as [1], [2], [3].
  - `main.py` feeds the evidence into `Qwen 2.5 3B` (Synthesizer model).
  - The model streams:
      "MS Dhoni has been appointed as the new mentor of Chennai Super Kings. [1] [2]"
  - Prints verified source links directly below the answer.
